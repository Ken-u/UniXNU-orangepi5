1. Driver host tests (package/Rk3588Nvme, see its README):
     g++ -std=c++17 -Wall -Wextra -Werror -O1 -I . tests/test-nvme-host.cpp -o /tmp/test-nvme-host && /tmp/test-nvme-host
       -> all NVMe host checks passed
     g++ -std=c++17 -Wall -Wextra -Werror -O1 -I . tests/test-root-manifest.cpp -o /tmp/test-root-manifest && /tmp/test-root-manifest
       -> test-root-manifest: ok
   The first runs NvmeHost.h and Gpt.h against a model of an NVMe controller that enforces the reset order, doorbells, the DMA window, PRP
   alignment, phase bits, queue ids, the completion-queue head doorbell and the write range, behind a non-coherent cache model.
   Seven mutations of NvmeHost.h are each caught (9 to 235 failed checks): no controller reset, the phase bit ignored, the phase not
   flipped on wrap, no flush before reading the data, no flush before polling a completion, no head doorbell, writes allowed outside the
   range, and the range off by one block. The head-doorbell mutation survived the first version of the model; the model now stalls a
   full completion queue (commit 5cbaf4236c5f0a850a62daa341b1195956b4a63f).
