Both aborts are in AcpiTableDxe (ELR at offset 0x11D0 of its image, loaded at 0xEF457000 in memG and 0xEF07E000 in memJ) and the registers hold 0xAFAFAFAF
(X25, V0). Which line of AcpiTableDxe reads the freed memory was not traced. What was found, on the host, is why the sixth table is garbage:

Pptt.aslc (edk2-rockchip, Silicon/Rockchip/RK3588/AcpiTables) compiled with clang puts an 8-byte pointer (ReferenceAcpiTable, .data.rel.ro) in front of the table (.data).
llvm-objdump -h of the build tree object (the order is the compiler's, the same with and without the fix):
  Idx Name              Size     VMA              Type
    2 .text             00000000 0000000000000000 TEXT
    3 .data.rel.ro      00000008 0000000000000000 DATA
    4 .rela.data.rel.ro 00000018 0000000000000000
    5 .data             00000220 0000000000000000 DATA
GenFw -c (the ACPI conversion) copies the data sections as the linker ordered them and only checks the length; so Pptt.acpi starts with the pointer. The same link
command as the build's (clang -target aarch64-linux-gnu -fuse-ld=lld ... -Wl,--entry,ReferenceAcpiTable ... Pptt.obj, GccBase.lds) run by hand, then GenFw -c,
without and with -Wl,--sort-section=name (the first 16 bytes of Pptt.acpi; the table is 0x220 = 544 bytes long):
  before: 00000000: 4002 0000 0000 0000 5050 5454 2002 0000   @.......PPTT ...
  after:  00000000: 5050 5454 2002 0000 0100 524b 4350 2020   PPTT ....RKCP
The "signature" the firmware read is the first four bytes 40 02 00 00 ("@" 02 00 00, printed "@?"), its length the next four, 0. With --sort-section=name (.data before
.data.rel.ro) the table comes first. The fix is that flag for the AcpiTables module in UniXNUOrangePi5.dsc (uefi-orangepi5 dc08d7c). On the board, memK (the fix
only, window 0xA0000000) installs all eight tables, and the line about the DSDT is gone:

[   7.331] - Found 'FACP' ACPI Table
[   7.349] - Found 'GTDT' ACPI Table
[   7.349] - Found 'APIC' ACPI Table
[   7.349] - Found 'MCFG' ACPI Table
[   7.349] - Found 'PPTT' ACPI Table

memL is memJ plus the fix, same window 0xE0000000, RtkUndiDxe again at 0xE7CFB000: no abort, the boot goes on (section 6). The memG build (no network stack) was not
repeated with the fix. Host reading: the broken PPTT install is what leaves the ACPI protocol in a state that some memory layouts turn into an abort; the layouts of memG
and memJ were not the cause of it.

7. What the ADT can carry (host reading, not a hardware observation)
--------------------------------------------------------------------
The ADT generator of UniXNU takes one memory range (payload.dram_size, the DTS memory node) and DarwinBoot one window (darwinboot-memory-size in /chosen,
256 MiB to 8 GiB in 2 MiB steps). The kernel gets its memory from the window and the boot arguments, not from the DTS node; nothing that reads dram-base or
dram-size in /chosen was found in the kernel sources of this tree. So the 3.75 GiB bank below 0xf0000000 and the 4 GiB above 0x100000000 cannot both
be given to the kernel, and the 256 MiB at 0x2f0000000 that U-Boot reports are mapped by edk2 nowhere. The ADT of the committed board.toml (14112 bytes, read back
from the file): darwinboot-memory-size 0xF8000000, dram-base 4294967296 (0x100000000), dram-size 4160749568 (0xF8000000).

8. How the runs were made (no hands at the board)
-------------------------------------------------
Files on the ESP were replaced from the build host through the U-Boot prompt (uboot-put.py of the SoC repository sends the file with YMODEM over the console,
fatwrite writes it, fatload and crc32 verify it). Output for the committed unixnu.toml of that day (all numbers hex, as U-Boot reads them):

=> fatwrite nvme 0:1 0x1000000 EFI/UniXNU/unixnu.toml 0x75e

=> fatload nvme 0:1 0x3000000 EFI/UniXNU/unixnu.toml

The same for uefi-launcher.img (5251560 bytes; crc32 51ebc4c4 for e35d303, aac42459 for dc08d7c, 4509baf4 for e1ac136) and kernel.macho.adt (14112 bytes; crc32 6f7e713f
for the 2.5 GiB ADT, 1b5749ed for the committed 3.875 GiB one); the transfer of the launcher takes about 40 s at 1.5 Mbaud. The window size of the trial runs was patched
